# 胶片色彩 / 白平衡 —— 产品优化方向（持续更新）

> 用途：新对话窗口先加载本文件进上下文，了解"胶片色彩/白平衡/胶片档案"这块讨论到了哪里。
> 性质：产品方向与设计结论的记录，不是实现 PR。实现相关的事实（bug、代码位置）以当时代码为准。
> 最近更新：2026-08-14

---

## 0. 一句话结论

当前"自动白平衡"用的是**白点法（99 分位）**，但胶片扫描的颜色问题**不是逐帧猜光源的问题，而是"设备标定 + 胶片特性"分层的问题**：

- **片基色罩（mask）= 设备相关** → 永远用吸管现采，preset 里存绝对值无意义。
- **胶片特性曲线（方向）= 设备无关** → 可随软件带，但必须应用在"片基归一化之后"。
- **幅度 = 部分设备相关** → 交给用户一个强度旋钮（或设备标定）微调。

方向上，把现在的 `preset`（标量集合）升级成 `film_profile`（标量 + 每通道曲线）。

## 1. 当前自动白平衡机制（事实）

代码在 `cli/lib/process_film.py`：

1. **采白点** `get_white_point_manual`（`:79`）：在 ROI（或整图）内，R/G/B **各自独立**取第 99 百分位，作为白点 `[r_w, g_w, b_w]`。这是**白点法（white-patch）**，不是灰度世界。
2. **算增益**（`:311-344`）：
   - `auto`：`gains = 1 / white_point_vec`，把三个 99 分位强制拉成 1:1:1。
   - `x,y`（`--white-balance x,y`，x=色温、y=色调，范围 [-50,50]）：在 AWB 基础上叠加偏移
     ```python
     gains[0] = awb_gains[0] * (1.0 + shift_x)  # 红（shift_x = x/100）
     gains[2] = awb_gains[2] * (1.0 - shift_x)  # 蓝
     gains[1] = awb_gains[1] * (1.0 - shift_y)  # 绿
     ```
   - `none`：只按最亮通道拉满曝光，不改比例。
3. **再归一化**：`gains /= max(white_point_vec * gains)`，维持曝光、只动色调。

**隐含假设（局限）**：白点法默认"最亮 1% = 中性白"。对胶片，这个最亮点是**完全曝光区（D-max）**，而 D-max 未必中性（三个染料层最大密度处饱和特性不一致），所以拿它当白点可能引入偏色。

## 2. 已知 bug：白平衡方向翻转（已定位，未修复）

**现象**：界面标识"色温正=黄、色调正=红（品红）"，但实际出图相反——色温正变蓝、色调正变绿。

**排查结论**：`gain` 公式本身符号是**对的**（temp 正 = 红升蓝降 = 暖），UI→序列化→CLI→`off_x/off_y` 全链路**无符号翻转**。根因是 WB 偏移被应用在管线前段（`img *= gains`，`:343`），被后面两个逐通道步骤反咬：

1. **gamma 对齐**（`:346-359`）：以**绿色通道中位数为基准**对齐 R/B 中间调 → 把"红升蓝降"又拉回绿，方向相反。
2. **auto levels**（`:404-437`）：逐通道 `(x-low)/(high-low)` min-max 拉伸，强制白点/黑点归中，抵消白点偏移。

作者自己在 `:439-442` 的注释已经意识到 auto levels 会约掉乘法增益（所以把 exposure 放在它之后），但 WB 偏移却放在了前面。

**修复方向**：把**手动 (x,y) 偏移**从 `:343` 挪到 **auto levels 之后、与 exposure 并排**，作为最终逐通道增益；AWB 基础增益（`awb_gains`）可留在前段（先把白点大致拉中性，方便 gamma 对齐）。

## 3. 胶片色彩科学关键结论

1. **白点法要的不是"高光"，是"中性亮参考"**。暗光下的白纸也能当参考；真正危险是"最亮像素不是中性色"（红苹果/夕阳/黄墙）。→ 采对参考点比换算法更重要。
2. **片基（未曝光底边）反转后是黑**，是**黑点参考**；**完全曝光（D-max）反转后才是白**。之前误把片基当白点参考，已纠正。
3. **不均匀偏色（暗部品、亮部蓝）来自三层染料（青/品/黄）各自不同的密度-曝光特征曲线**，是**确定性签名**（同一种卷可复现），不是随机化学噪声。
4. **单点 WB（每通道常数乘子）只能修均匀偏色**；随亮度改变方向的偏色必须用**逐通道曲线**（或 shadow/mid/highlight 分色）才能修。
5. **"胶卷不精确"要分开看**：卷与卷差异/老化/冲卷温度 = 随机，该谅解；系统性偏色 = 确定、可标定，该修掉（"保留偏色"是主动审美选择，不等于"修不了就算了"）。

## 4. NLP 参考（Negative Lab Pro）

**完整流程**：采集 RAW → 导入 LR → 预处理 → 转换 → 精修 → 导出。

与本问题相关的关键点：

- **吸管只干一件事：点空白片基 → 中和橙罩**（不是点黑/白/灰三点）。做完裁掉底边（`border buffer` 排除边缘）。
- **黑白点全图自适应找**，不是用户点。转换时"平移/倾斜/弯曲"色调曲线。
- **跨帧一致性**：`Match`（选参考帧统一同光源多帧颜色）+ `Roll Analysis`。
- **色彩模型**：`Basic / Frontier / Noritsu / B+W` = 冲扫机风格模拟（Lab look），不是简单的逐通道参数。
- **黑白负片有独立 B+W 模式**（黑白无橙罩，反转逻辑不同）。

**与我们系统的差异对照**（当时盘点）：

| 维度 | NLP | 我们 |
|---|---|---|
| 黑白点定位 | 全图自适应 | 手动 ROI（99 / 0.01 / 99.99 分位） |
| 去橙罩 | LR 吸管点片基（采 LR 处理后的图） | 后端吸管读源 RAW/TIFF（更"源真实"） |
| 色彩模型 | Frontier/Noritsu Lab look | skin_protect/balanced/deep/preserve（gamma 力度 + 肤色保护） |
| 跨帧一致性 | Match + Roll Analysis | 固定参数批处理（无参考帧匹配） |
| 黑白负片 | 显式 B+W | 无（当前管线假设彩负） |
| 非破坏性 | LR 参数化可回改 | 烘焙 TIFF |

**后端吸管**：`cli/lib/tool/pick.py::pick_color`（`:60`）从原始 RAW/TIFF 读单像素（受控 demosaic、`use_camera_wb`），经 `pick-color` IPC → `openlucky.py:1311` → 填进 mask。取完自动进入白点框选。

## 5. 核心架构结论（最重要）

### 5.1 三层"设备相关"拆解

| 层 | 跨设备吗 | 处置 |
|---|---|---|
| mask 绝对值（片基 RGB） | **否**（相机/扫描仪/光源都不同） | 永远吸管现采 |
| 胶片特性曲线的**方向**（如"柯达偏暖→加冷"） | **是**（染料组的光谱事实，方向翻不了） | 随软件带 |
| 胶片特性曲线的**幅度/精确形状** | **部分**（设备增益/伽马缩放幅度） | 强度旋钮 / 设备标定 |

### 5.2 正确形态

1. **片基中性化（吸管点片基）= 设备标定**，永远现采。preset 里的 `mask_r/g/b` 绝对值应**删**。
2. **胶片特性曲线**（方向 + 大致形状）随软件带，但**应用在片基归一化之后**。
3. **逐张残余**：shadow/mid/highlight 分色（Lightroom Color Grading 那套），用于冲卷/灯光/批次等随机差异。自由贝塞尔曲线是最后手段，非首选。

### 5.3 preset → film_profile

不是"淘汰 preset"，是**升级成胶片档案**（否则和"随软件带的曲线"两套名字混淆）：

| 旧 preset 字段 | 处置 |
|---|---|
| `label` | 留 |
| `mask_r/g/b` | **删**（设备相关，吸管现采；最多留一个"兜底/批处理默认"） |
| `gamma` / `contrast` / `contrast_r/g/b` | **被每通道 curve 取代** |
| `saturation` | 留（跨通道，曲线替不掉） |
| `white_balance` / `tone` / `rotate_clockwise` | 另一回事（每张图保存状态，非卷特征） |

新结构：

```yaml
film_profiles:
  kodak_ultramax_400:
    label: "Kodak UltraMax 400 ..."
    curve:            # 每通道特性曲线（方向 + 形状，应用在片基归一化后）
      r: [...]        # 或 LUT / 分位点
      g: [...]
      b: [...]
    saturation: 1.15
```
