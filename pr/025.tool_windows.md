# 工具窗体（Tool Windows）

## 定位

把除尘等"专用工具"从主窗体中拆出来，各自弹出独立窗体完成工作。本期实现除尘工具窗，未来划痕、其它工具复用同一套机制。

## 入口（本期待定）

除尘从 **PhotoEdit 内部**进入：PhotoEdit 里的某个按钮或菜单点击后 `openToolWindow('dust', { photo, workingDir })`，payload 带当前选中照片的上下文。具体按钮/菜单位置待定，不阻塞窗口机制设计。

## 窗体形态：子窗口，接受主窗被锁

- 工具窗用 `new BrowserWindow({ parent: 主窗 })` 创建，**始终浮在主窗之上**。
- 已知行为（Windows）：子窗打开期间主窗无法聚焦/点击——**接受这个限制**，作为产品行为。
- 因此工具窗与主窗的工作流是：
  - 除尘窗开着 → 只能接着处理当前照片；
  - 换照片 → 先关除尘窗，主窗解锁，选下一张，再点"除尘"。
- 不需要"按照片去重/换照片重开"逻辑——父窗被锁使该路径不存在。
- 主窗关闭 → Windows 子窗随父窗关闭，无需额外处理；`window-all-closed` 退出逻辑不变。

## 单例

同一工具同一时刻**最多一个窗体**。父窗被锁天然保证用户路径不会重复打开；窗口管理器再加一道守卫，程序化触发（快捷键/批量）也不会开出第二个。

## 窗口管理器（主进程）

新模块 `app/main/tool-windows.js`：

```js
const windows = new Map()   // tool -> { win, payload, ownerWin }

function openToolWindow(tool, payload, ownerWin) {
  if (windows.has(tool)) return null            // 单例守卫：已开则不新建、不聚焦
  const win = new BrowserWindow({
    parent: ownerWin,
    width, height,                               // 来自 TOOLS 注册表
    webPreferences: { /* 与主窗一致 */ }
  })
  win.loadFile('dist/index.html', { query: { tool } })   // 工具 ID 走 URL，payload 不走 URL
  windows.set(tool, { win, payload, ownerWinId: ownerWin.id })
  win.on('closed', () => windows.delete(tool))
  return win.id
}

function getToolContext(win)  { /* 按 win.id 反查 tool 拿 payload */ }
function notifyOwner(tool, result) { /* 找到 owner 主窗，webContents.send */ }
```

## 契约条目

`backend-contract.js` 新增 3 条（`capabilities` 加 `['window']`）：

| id | 实现 | 说明 |
|---|---|---|
| `open-tool-window` | custom-handler | `{ tool, payload }` → 创建子窗 |
| `get-tool-context` | custom-handler | 工具窗加载后拉取自己的 payload |
| `tool-result` | custom-handler | 工具窗回传结果，转发主窗 |

## 渲染层

- 工具窗与主窗加载同一 bundle；`App.vue` 挂载时读 `?tool=dust` → 渲染 `<DustTool/>`，否则渲染正常 App。
- facade 抽换点加 3 个方法（`electron.js` / 未来 `tauri.js` 各自实现）：

```js
export const openToolWindow   = (tool, payload) => invoke('open-tool-window', { tool, payload })
export const getToolContext   = () => invoke('get-tool-context')
export const notifyToolResult = (tool, result) => send('tool-result', { tool, result })
```

## 工具窗数据流（以除尘为例）

工具窗是"配置生成器"，处理仍走主管线，因此**不需要新的处理 IPC**：

```
主窗（PhotoEdit）──openToolWindow('dust', { photo, workingDir })──→ 创建子窗
DustTool 挂载 ──getToolContext()──→ 拿 photo/workingDir
DustTool 预览 ──apply-filmparam(现有，payload 带 dust ROIs + 滑块)──→ 复用现有预览链路
DustTool 确认 ──notifyToolResult('dust', { photo, dust: {...} })──→ 主进程转发主窗
主窗收结果 ──并入该照片 params──→ 刷新当前照片预览
```

dust 参数只是 `apply-filmparam` payload 新增字段，CLI 侧见 `pr/024.dust.md`（`--dust` + `--dust-rois`）。

## Tauri 迁移映射

| 契约条目 | Electron | Tauri/Rust |
|---|---|---|
| `open-tool-window` | `new BrowserWindow({ parent })` | Rust command `WindowBuilder::parent(...).build()` |
| `get-tool-context` | 注册表按 `win.id` 取 | Rust command 参数带 `Window`，按 label 查 store |
| `tool-result` | `send` + 注册表找 owner | `AppHandle.emit` / 目标 `Window.emit` |
| 子窗口 | `parent` | `WindowBuilder::parent`（原生支持） |
| 事件回发调用者 | `event.sender.send` | Rust command 的 `Window` 参数 |

`capabilities: ['window']` 成为迁移清单新行。渲染层、工具 UI、dust 算法跨引擎共享，只换适配器。
